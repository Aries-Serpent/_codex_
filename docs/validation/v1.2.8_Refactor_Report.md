## Critical Finding: Split-Brain Architecture Issue

### Problem Identified
Code review revealed that the refactoring assumed `src.training.*` modules exist, but:

1. **Root `training/`** contains:
   - `engine_hf_trainer.py` ✅
   - `functional_training.py` ✅
   - `checkpoint_manager.py` ✅
   - `data_utils.py` ✅
   - Other actual implementation modules

2. **`src/training/`** contains:
   - `trainer.py` ✅
   - `simple_trainer.py` ✅
   - `checkpointing.py` ✅
   - DIFFERENT set of modules

3. **Root `training/__init__.py`** is a compatibility shim that imports FROM `src.training.trainer`

### Implication
Changing imports from `training.engine_hf_trainer` to `src.training.engine_hf_trainer` will FAIL at runtime because `engine_hf_trainer.py` doesn't exist in `src/training/`.

### Architecture Options

**Option A: Move modules to src/training/** (Recommended)
- Move `training/*.py` modules to `src/training/`
- Keep root `training/` as pure compatibility shim
- Benefits: Clean structure, single canonical location
- Cost: Significant file moves, potential breakage

**Option B: Expand compatibility shim**
- Keep modules in root `training/`
- Expand `training/__init__.py` to re-export all modules
- Update src/training/__init__.py to import from root training
- Benefits: Less disruptive
- Cost: Maintains split-brain

**Option C: Revert refactoring** (Safest short-term)
- Revert batches 1-7
- Keep imports as `training.*` (canonical location)
- Document that root `training/` IS the canonical location
- Benefits: No runtime errors
- Cost: Doesn't resolve split-brain
