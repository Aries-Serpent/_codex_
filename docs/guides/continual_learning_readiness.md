# Continual learning readiness overview

**Last Updated:** 2026-06-22

The table below summarises the infrastructure already present in `codex-universal` that can be leveraged when introducing continual learning or broader skill acquisition workflows. It also highlights key opportunities to extend each area.

| Layer | Existing assets | Continual learning leverage | Suggested next steps |
| --- | --- | --- | --- |
| Configuration & orchestration | Hydra entrypoint composes structured configs, merges repo defaults, and routes through the current training shim while negotiating distributed startup. 【F:src/codex_ml/cli/hydra_main.py†L15-L140】 | Use Hydra to stage curriculum phases (e.g., alternating datasets or adapters) and reuse the distributed bootstrap hooks when scaling continual updates. | Compose `configs/training/continual/rehearsal.yaml` with the streaming data module to bootstrap rehearsal-style updates while keeping overrides declarative. |
| Unified training core | `UnifiedTrainingConfig` enforces hyperparameter bounds, seeds every dependency, selects a backend, and persists epoch checkpoints with metadata rich enough for resumption and audit. 【F:src/codex_ml/training/unified_training.py†L45-L200】 | Treat the orchestrator as the control loop for continual updates: reuse deterministic seeding, callback hooks, and structured checkpoint directories to stitch episodic learning sessions. | Add streaming-dataset callbacks and policies for merging/examining historical checkpoints (e.g., keep-last by performance tiers rather than epoch order). |
| Checkpoint services | `checkpoint_core` captures RNG/environment provenance, serialises payloads robustly, and maintains an index with metric-aware pruning. 【F:src/codex_ml/utils/checkpoint_core.py†L1-L399】 | Snapshotting RNG and environment state enables reproducible replay of prior tasks, while index pruning can be adapted to retain diverse skill anchors across continual runs. | Extend metadata to record task descriptors or rehearsal buffers, and surface APIs to query checkpoints by skill/task tags. |
| Data modules | Lightweight `DataModule` offers deterministic shuffling and iterable batches for smoke datasets. 【F:src/codex_ml/data/datamodule.py†L8-L29】 | Use the deterministic hooks to validate curriculum transitions and rehearsal sampling strategies before wiring heavier dataloaders. | Expand into streaming/online loaders with replay buffers and concept-drift detectors while preserving reproducibility toggles. Pair with `codex_ml.data.datamodule.StreamingDataModule` for JSONL ingestion. |
| Telemetry & logging | Logging utilities negotiate optional TensorBoard/MLflow writers and fall back to NDJSON metrics when dependencies are absent. 【F:src/logging_utils.py†L1-L200】 | Capture long-horizon metrics (forgetting scores, competency drift) by feeding them through the existing unified logging API and persisting to the fallback channel for offline review. | Introduce continual-learning metric schemas (e.g., average accuracy, forgetting) and ensure fallback logging can be forced on even when system metrics libraries exist. |
| Quality gates | Regression test ensures functional training keeps emitting per-epoch metrics even with optional deps stubbed out. 【F:tests/test_training_eval.py†L12-L44】 | Use this pattern to guard continual-learning loops by simulating missing toolchains or degraded environments, ensuring adaptive behaviours remain observable. | Add parity tests for unified orchestrator checkpoints and metric summaries under curriculum-style configs. |
