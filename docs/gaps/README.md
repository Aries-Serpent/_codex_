# Gap Registry Overview

This directory contains documentation related to the **Gap Registry** used by
the `_codex_` project.

The registry itself is stored in `codex_gap_registry.yaml` at the repository
root and is generated by:

- `tools/codex_gap_registry.py`
- `tools/codex_yaml_gap_check.py` (for coverage validation)

The Gap Registry is populated from:

- The latest `_codex_: Status Update (YYYY-MM-DD)` audit markdown.
- The `codex_change_log.md` produced by the task sequence runner.
- The `codex_error_questions.md` file containing structured error prompts.

## Registry schema (logical)

The YAML structure looks like:

```yaml
gaps:
  - id: tokenization.fast_backend
    capability: tokenization
    location: ["src/codex_ml/tokenization", "tests/codex_ml/test_fast_tokenizer.py"]
    description: "Fast tokenizer backend missing, parity tests absent"
    status: missing        # or stubbed|partial|implemented
    risk_level: medium     # optional, Phase 5 come from Hardship Map
    yaml_phase_step: "3.1" # phase.step id from codex_task_sequence.yaml
    ml_test_categories: ["data", "model"]
    last_seen_in_audit: "Previous Cycle-11-27"
    notes: "Extracted from High-Signal Findings in audit."
```

The exact fields Phase 5 evolve over time as the project matures.

## Per-gap docs stubs

The helper script:
- `tools/codex_gap_bootstrap.py`

can be used to create per-gap documentation stubs under this directory:
- `docs/gaps/<gap_id>.md`

Each stub typically includes:
- Basic metadata (capability, status).
- A copy of the gap description from the registry.
- Space for design notes, constraints, and acceptance criteria.

## Trends and snapshots

The helper script:
- `tools/codex_gap_trends.py`

can summarize the current registry into:
- `codex_gap_trends.md`

with aggregate counts by status and capability.
