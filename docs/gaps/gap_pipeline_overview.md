# _codex_ Gap Pipeline Overview

This document describes how the Gap Registry, YAML task sequence, and runner
work together to track and resolve implementation gaps across the `_codex_`
project.

## Components

- `codex_gap_registry.yaml`
  - Machine-readable list of gaps (id, capability, location, status, etc.).
  - Generated by `tools/codex_gap_registry.py`.
- `codex_yaml_gap_report.md`
  - Coverage report between the registry and `codex_task_sequence.yaml`.
  - Generated by `tools/codex_yaml_gap_check.py`.
- `codex_gap_trends.md`
  - Snapshot view of counts by status and capability.
  - Generated by `tools/codex_gap_trends.py`.
- `docs/gaps/<gap_id>.md`
  - Per-gap design/notes stubs.
  - Created/updated by `tools/codex_gap_bootstrap.py`.
- `codex_task_sequence.yaml`
  - Declarative sequence of phases and steps for resolving gaps.
- `tools/codex_task_sequence_runner.py`
  - Executes the sequence and records outcomes to:
    - `codex_change_log.md`
    - `codex_error_questions.md`
- `run_codex_task_sequence.sh`
  - Thin shell wrapper around the Python runner.

## Typical flow

1. Produce or update a status audit:
   - `_codex_status_update-YYYY-MM-DD.md`.
2. Run the task sequence (or at least the Search & Mapping phase):
   - `./run_codex_task_sequence.sh codex_task_sequence.yaml _codex_status_update-YYYY-MM-DD.md`
3. Inspect outputs:
   - `codex_gap_registry.yaml`
   - `codex_yaml_gap_report.md`
   - `codex_gap_trends.md`
   - `codex_change_log.md`
   - `codex_error_questions.md`
4. For a given gap id:
   - `python tools/codex_gap_bootstrap.py <gap_id>`
   - Edit `docs/gaps/<gap_id>.md`.
   - Implement code + tests in the suggested locations.
5. Re-run the sequence and registry tools as needed.

## Policy hooks

- `status` values (`missing`, `stubbed`, `partial`, `implemented`) and
  `risk_level` are intended to align with higher-level policies (e.g. hardship
  maps, test coverage expectations).
- `yaml_phase_step` links a gap to a specific step in
  `codex_task_sequence.yaml`, ensuring there is a concrete plan of action.
- `codex_error_questions.md` is the canonical place to capture structured
  questions back to ChatGPT @codex when a step fails.

This pipeline is deliberately conservative:
- No cost-incurring CI or Actions are introduced.
- All work is meant to run on a local, offline Codex environment.
