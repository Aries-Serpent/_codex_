## 🚀 Deployment Procedure (Blue-Green)

### Phase 1: Blue Environment Setup (0-20 minutes)

#### Step 1: Pull Latest Code
```bash
cd /opt/codex
git checkout main
git pull origin main
git verify-commit HEAD  # Verify signed commit
```

#### Step 2: Build Docker Image
```bash
docker build -t codex:v0.2.0 \
  --build-arg VERSION=v0.2.0 \
  --build-arg BUILD_DATE=$(date -u +%Y-%m-%dT%H:%M:%SZ) \
  --build-arg VCS_REF=$(git rev-parse --short HEAD) \
  .

# Verify image
docker inspect codex:v0.2.0 | jq '.Config.Env'
```

#### Step 3: Security Scan Image
```bash
trivy image --severity HIGH,CRITICAL codex:v0.2.0

# Expected: No HIGH/CRITICAL vulnerabilities found
# If found, escalate immediately
```

#### Step 4: Push to Registry
```bash
# Login to registry (assumes credentials in .docker/config.json)
docker login -u $REGISTRY_USER -p $REGISTRY_PASSWORD $REGISTRY_URL

# Tag and push
docker tag codex:v0.2.0 $REGISTRY_URL/codex:v0.2.0
docker tag codex:v0.2.0 $REGISTRY_URL/codex:latest
docker push $REGISTRY_URL/codex:v0.2.0
docker push $REGISTRY_URL/codex:latest

# Verify push
curl -s $REGISTRY_URL/v2/codex/manifests/v0.2.0 -H "Accept: application/vnd.docker.distribution.manifest.v2+json" | jq .digest
```

#### Step 5: Deploy to Blue Environment
```bash
# Create blue namespace if not exists
kubectl create namespace codex-blue --dry-run=client -o yaml | kubectl apply -f -

# Deploy application
kubectl set image deployment/codex codex=$REGISTRY_URL/codex:v0.2.0 \
  --namespace=codex-blue \
  --record

# Wait for rollout
kubectl rollout status deployment/codex -n codex-blue --timeout=5m

# Expected: deployment "codex" successfully rolled out
```

#### Step 6: Verify Blue Environment
```bash
# Port forward to test
kubectl port-forward svc/codex 8000:8000 -n codex-blue &

# Health check
curl -s http://localhost:8000/api/health | jq .

# Expected: 
# {
#   "status": "healthy",
#   "version": "v0.2.0",
#   "database": "connected",
#   "cache": "connected"
# }

# Performance baseline test
ab -n 100 -c 10 http://localhost:8000/api/test

# Expected: Requests/sec > 150 RPS (Phase 8 baseline)
```

### Phase 2: Cutover (20-40 minutes)

#### Step 7: Update Load Balancer Configuration
```bash
# Current state: 100% traffic → Green (v0.1.0)

# Switch traffic gradually (canary: 10% Blue, 90% Green)
kubectl patch service codex -p '{"spec": {"selector": {"version": "canary"}}}' \
  --namespace=default

# Wait 2 minutes to monitor metrics
sleep 120
```

#### Step 8: Monitor Canary Metrics
```bash
# Query Datadog for error rate
curl -s "https://api.datadoghq.com/api/v1/series?query=trace.web.request.errors&from=$(date -d '2 min ago' +%s)&to=$(date +%s)" \
  -H "DD-API-KEY: $DD_API_KEY" \
  -H "DD-APPLICATION-KEY: $DD_APP_KEY" | jq .

# Expected: Error rate < 0.5% (Phase 8 baseline: 0.4%)
# If error rate > 1.0%, rollback immediately
```

#### Step 9: Gradually Increase Traffic
```bash
# Increase to 50% Blue traffic
kubectl patch service codex -p \
  '{"spec": {"sessionAffinity": "ClientIP", "trafficPolicy": "Local", "loadBalancerSourceRanges": []}}' \
  --namespace=default

# Update Istio virtual service or nginx ingress
kubectl patch virtualservice codex -p '{"spec": {"hosts": [{"name": "codex", "http": [{"match": [{"uri": {"prefix": "/"}}], "route": [{"destination": {"host": "codex", "subset": "v0.2.0"}, "weight": 50}, {"destination": {"host": "codex", "subset": "v0.1.0"}, "weight": 50}]}]}]}}' \
  --namespace=default

# Wait 5 minutes to observe metrics
sleep 300
```

#### Step 10: Verify Metrics at 50%
```bash
# Check throughput
curl -s "https://api.datadoghq.com/api/v1/series?query=trace.web.request.throughput" \
  -H "DD-API-KEY: $DD_API_KEY" | jq '.series[0].points | tail -1'

# Expected: 75+ RPS (50% of 152.7 RPS baseline)

# Check latency
curl -s "https://api.datadoghq.com/api/v1/series?query=trace.web.request.latency.p95" \
  -H "DD-API-KEY: $DD_API_KEY" | jq '.series[0].points | tail -1'

# Expected: p95 latency < 150ms (slightly higher due to canary overhead)

# Check error rate
curl -s "https://api.datadoghq.com/api/v1/series?query=trace.web.request.errors" \
  -H "DD-API-KEY: $DD_API_KEY" | jq '.series[0].points | tail -1'

# Expected: Error rate < 1.0%
```

#### Step 11: Full Cutover (100% Blue)
```bash
# Update virtual service to 100% Blue
kubectl patch virtualservice codex -p '{"spec": {"hosts": [{"name": "codex", "http": [{"match": [{"uri": {"prefix": "/"}}], "route": [{"destination": {"host": "codex", "subset": "v0.2.0"}, "weight": 100}]}]}]}}' \
  --namespace=default

# Wait 2 minutes
sleep 120

# Verify cutover
kubectl get service codex -o jsonpath='{.spec.selector.version}'

# Expected: v0.2.0
```

## ✅ Health Check Procedure

### Immediate Post-Deployment (First 5 Minutes)

```bash
#!/bin/bash
# health-check-immediate.sh

echo "🔍 Immediate Health Checks (v0.2.0)"
echo "===================================="

# API Availability
echo -n "API Availability: "
if curl -s http://codex.example.com/api/health | jq -e '.status=="healthy"' > /dev/null; then
  echo "✅ PASS"
else
  echo "❌ FAIL"
  exit 1
fi

# Database Connectivity
echo -n "Database: "
if curl -s http://codex.example.com/api/health | jq -e '.database=="connected"' > /dev/null; then
  echo "✅ PASS"
else
  echo "❌ FAIL"
  exit 1
fi

# Cache Status
echo -n "Cache: "
if curl -s http://codex.example.com/api/health | jq -e '.cache=="connected"' > /dev/null; then
  echo "✅ PASS"
else
  echo "❌ FAIL"
  exit 1
fi

# Version Check
echo -n "Version: "
VERSION=$(curl -s http://codex.example.com/api/health | jq -r .version)
if [ "$VERSION" == "v0.2.0" ]; then
  echo "✅ PASS ($VERSION)"
else
  echo "❌ FAIL (expected v0.2.0, got $VERSION)"
  exit 1
fi

echo ""
echo "✅ All immediate checks passed"
```

### Extended Health Checks (First 30 Minutes)

```bash
#!/bin/bash
# health-check-extended.sh

echo "🔍 Extended Health Checks (v0.2.0)"
echo "==================================="

# Performance Baseline
echo -n "Throughput (target >150 RPS): "
THROUGHPUT=$(ab -n 1000 -c 50 http://codex.example.com/api/test 2>/dev/null | grep "Requests per second" | awk '{print $NF}' | cut -d. -f1)
if [ "$THROUGHPUT" -gt 150 ]; then
  echo "✅ PASS ($THROUGHPUT RPS)"
else
  echo "⚠️  WARNING ($THROUGHPUT RPS < 150)"
fi

# Latency Check
echo -n "Latency p95 (target <120ms): "
LATENCY=$(ab -n 1000 -c 50 http://codex.example.com/api/test 2>/dev/null | grep "95%" | awk '{print $NF}' | cut -d. -f1)
if [ "$LATENCY" -lt 120 ]; then
  echo "✅ PASS (${LATENCY}ms)"
else
  echo "⚠️  WARNING (${LATENCY}ms > 120)"
fi

# Error Rate
echo -n "Error Rate (target <1%): "
ERROR_RATE=$(ab -n 1000 -c 50 http://codex.example.com/api/test 2>/dev/null | grep "Failed requests" | awk '{print $3}')
PERCENT=$((ERROR_RATE * 100 / 1000))
if [ "$PERCENT" -lt 1 ]; then
  echo "✅ PASS (${PERCENT}%)"
else
  echo "❌ FAIL (${PERCENT}%)"
  exit 1
fi

echo ""
echo "✅ Extended health checks complete"
```

## 🔄 Incident Response Procedures

### Scenario 1: High Error Rate Detected (>5%)

**Trigger**: Automated alert from Datadog  
**Response Time**: <5 minutes

```bash
# Step 1: Assess severity
ERROR_RATE=$(curl -s "https://api.datadoghq.com/api/v1/series?query=trace.web.request.errors" \
  -H "DD-API-KEY: $DD_API_KEY" | jq '.series[0].points | tail -1 | .[1]')

if [ "$ERROR_RATE" -gt 5 ]; then
  echo "🚨 ERROR RATE CRITICAL: ${ERROR_RATE}%"
  
  # Step 2: Check error logs
  kubectl logs -n codex-blue -l app=codex --tail=50 | grep ERROR
  
  # Step 3: Drain traffic from Blue
  kubectl patch virtualservice codex -p '{"spec": {"hosts": [{"name": "codex", "http": [{"match": [{"uri": {"prefix": "/"}}], "route": [{"destination": {"host": "codex", "subset": "v0.1.0"}, "weight": 100}]}]}]}}' \
    --namespace=default
  
  # Step 4: Escalate to on-call engineer
  curl -X POST https://events.pagerduty.com/v2/enqueue \
    -H "Content-Type: application/json" \
    -d "{
      \"routing_key\": \"$PAGERDUTY_ROUTING_KEY\",
      \"event_action\": \"trigger\",
      \"payload\": {
        \"summary\": \"Codex v0.2.0 deployment error rate >5%\",
        \"severity\": \"critical\",
        \"source\": \"Automated Incident Response\"
      }
    }"
  
  echo "✅ Fallback to v0.1.0 initiated"
  echo "⚠️  Incident escalated to PagerDuty"
fi
```

### Scenario 2: Database Connection Failure

**Trigger**: Health check fails  
**Response Time**: <2 minutes

```bash
# Step 1: Check database status
psql $PROD_DB_CONNECTION_STRING -c "SELECT 1;"

# Step 2: Check connection pool
kubectl exec -it pod/codex-blue-xxx -n codex-blue -- \
  curl -s http://localhost:8000/metrics | grep "db_pool"

# Step 3: Restart connection pool
kubectl rollout restart deployment/codex -n codex-blue

# Step 4: Verify recovery
sleep 30
curl -s http://codex.example.com/api/health | jq .
```

### Scenario 3: Memory Leak / Resource Exhaustion

**Trigger**: Memory usage >85%  
**Response Time**: <10 minutes

```bash
# Step 1: Monitor memory
kubectl top pod -n codex-blue

# Step 2: Check for memory leaks
kubectl logs -n codex-blue -l app=codex --tail=100 | grep "memory\|heap"

# Step 3: Trigger garbage collection (if applicable)
kubectl exec -it pod/codex-blue-xxx -n codex-blue -- \
  curl -X POST http://localhost:8000/admin/gc

# Step 4: If memory continues growing, restart pod
kubectl delete pod pod/codex-blue-xxx -n codex-blue
```

## ⏮️ Rollback Procedure

### Quick Rollback (v0.2.0 → v0.1.0)

**Target Duration**: <5 minutes

```bash
#!/bin/bash
# rollback-v0.1.0.sh

echo "🔄 Rolling back to v0.1.0..."

# Step 1: Verify v0.1.0 image is available
docker inspect $REGISTRY_URL/codex:v0.1.0 || {
  echo "❌ v0.1.0 image not found in registry"
  exit 1
}

# Step 2: Update deployment image
kubectl set image deployment/codex codex=$REGISTRY_URL/codex:v0.1.0 \
  --namespace=codex-blue \
  --record

# Step 3: Wait for rollout
kubectl rollout status deployment/codex -n codex-blue --timeout=2m

# Step 4: Switch traffic to v0.1.0
kubectl patch virtualservice codex -p '{"spec": {"hosts": [{"name": "codex", "http": [{"match": [{"uri": {"prefix": "/"}}], "route": [{"destination": {"host": "codex", "subset": "v0.1.0"}, "weight": 100}]}]}]}}' \
  --namespace=default

# Step 5: Verify rollback
sleep 30
VERSION=$(curl -s http://codex.example.com/api/health | jq -r .version)
if [ "$VERSION" == "v0.1.0" ]; then
  echo "✅ Rollback successful (v0.1.0 active)"
else
  echo "❌ Rollback failed (version: $VERSION)"
  exit 1
fi
```
