## Executive Summary

### Release Timeline
- **v0.2.2**: Successfully deployed 2026-07-13T04:00:50Z (TOKEN-BASED AUTH)
- **v0.3.0 Automated Attempts** (Runs #1064-1069): Failed 2026-07-18 to 2026-07-20 (OIDC AUTH FAILURES)
- **v0.3.0 Manual Success**: Successfully deployed 2026-07-20T03:32:58Z (TOKEN-BASED AUTH - REVERTED)

### Root Cause Identified
**OIDC Migration Failure**: Commit 4451f797 attempted to migrate to Trusted Publishing (OIDC) but PyPI rejected all OIDC tokens with "403 Invalid API Token: OIDC scoped token is not valid for project" errors. The token generation was successful, but PyPI's validation failed - indicating a configuration mismatch between the GitHub workflow and PyPI's Trusted Publisher settings.

### Key Finding
**v0.3.0 succeeded because the fix was to REVERT to token-based authentication**, which worked immediately. The OIDC implementation was abandoned within the same commit (4451f797) when OIDC failures became clear.

### Success Pattern
✅ Use **token-based authentication** with `secrets.PYPI_TOKEN`  
✅ Pin action to `ba38be9e` commit SHA (proven secure)  
✅ Ensure `skip-existing: false` (don't skip new versions)

### Error Pattern Analysis

All failed OIDC attempts show the same error:
```
HTTPError: 403 Forbidden from https://upload.pypi.org/legacy/
403 Invalid API Token: OIDC scoped token is not valid for project
```

**Error Characteristics**:
- ✅ OIDC token WAS generated by GitHub (sigstore verification passed)
- ✅ Token WAS sent to PyPI endpoint
- 🔴 PyPI rejected it due to scope mismatch
- **NOT** a "token generation" failure - it's a "token validation" failure

### Root Cause: OIDC Token Validation Failure

**Problem Chain**:
1. GitHub Actions generated valid OIDC token (confirmed by sigstore verification)
2. pypa/gh-action-pypi-publish exchanged token with PyPI
3. PyPI validated token claims against Trusted Publisher configuration
4. **Token claims didn't match PyPI's registered publisher**

**Likely Causes** (in order of probability):
1. ⚠️ **Workflow environment name mismatch**
   - Workflow configured: `environment: name: pypi`
   - PyPI expects: Possibly different (case-sensitive)
2. ⚠️ **Repository reference mismatch**
   - Workflow: `Aries-Serpent/_codex_`
   - PyPI registration: May expect different format
3. ⚠️ **Action version too old for proper OIDC**
   - Pinned: `ba38be9e` (April 2024)
   - Newer versions may have better OIDC support
4. ⚠️ **Trusted Publisher not fully configured**
   - Conditions may not all be set correctly in PyPI dashboard

## Part 4: Comparative Analysis

### Success Pattern Comparison

| Factor | v0.2.2 (SUCCESS) | v0.3.0 OIDC (FAILURE) | v0.3.0 Token (SUCCESS) |
|--------|------------------|----------------------|------------------------|
| **Auth Method** | Token-based | OIDC (Trusted Publisher) | Token-based |
| **Password Param** | ✅ Present | ❌ Removed | ✅ Present |
| **id-token Permission** | ❌ Not needed | ✅ Added | ❌ Not needed |
| **Action Version** | `cef22109...` | `ba38be9e` | `ba38be9e` |
| **Publish Result** | ✅ SUCCESS | 🔴 FAILED (403) | ✅ SUCCESS |
| **Root Cause** | N/A | PyPI token validation | N/A |
| **Time to Success** | 1 attempt | Failed 6x, succeeded with revert | 1 attempt |

### What Changed Between v0.2.2 and v0.3.0

1. **Attempted OIDC Migration** (Commit 4451f797)
   - Added `id-token: write` permissions
   - Removed `password` parameter
   - Upgraded action version to `ba38be9e`
   - Expected: Seamless migration to Trusted Publishing
   - Actual: All 6 runs (1064-1069) failed with 403 errors

2. **Root Cause of OIDC Failure**
   - PyPI Trusted Publisher configuration missing/incorrect
   - Workflow environment name/repo reference didn't match PyPI config
   - Action version might be too old for full OIDC support

3. **Solution Applied** (Within Commit 4451f797)
   - Reverted password parameter with `secrets.PYPI_TOKEN`
   - Removed id-token permissions (not needed for token auth)
   - Kept action pinned for security
   - Result: v0.3.0 published successfully

### Security Posture Comparison

| Aspect | v0.2.2 | v0.3.0 OIDC (Failed) | v0.3.0 Token (Current) |
|--------|--------|---------------------|------------------------|
| **Secret Storage** | API token in repo secrets | No secrets (OIDC) | API token in repo secrets |
| **Token Exposure** | Manual rotation needed | Auto-rotated by GitHub | Manual rotation needed |
| **Implementation Complexity** | Simple | Complex (config dependent) | Simple |
| **Audit Trail** | Action logs | Full sigstore attestation | Action logs |
| **Scope Control** | Broad (full PyPI write) | Fine-grained (per-project) | Broad (full PyPI write) |

**Assessment**: While OIDC is technically superior (auto-rotation, fine-grained scope), the token-based approach is currently more reliable due to PyPI configuration issues.

- Impact: Token claim `environment` field validation fails

- Workflow file name: `.github/workflows/pypi-publish.yml`

- Impact: Token claim `workflow` field validation fails

### Why These Weren't Caught Earlier

1. No testing was done in non-production environment first (TestPyPI)

## Appendix A: Complete v0.3.0 Workflow (Current - Token-Based)

```yaml
name: Publish Python Package to PyPI
on:
  release:
    types: [published]
  workflow_dispatch:
    inputs:
      environment:
        description: Target environment
        required: true
        type: choice
        options:
          - testpypi
          - pypi
        default: testpypi
concurrency:
  group: ${{ github.workflow }}-${{ github.head_ref || github.ref }}
  cancel-in-progress: false
permissions:
  contents: read

jobs:
  build:
    name: Build Distribution
    runs-on: ubuntu-latest
    timeout-minutes: 60
    steps:
      - uses: actions/checkout@v5
      - name: Set up Python 3.12 with tiered cache
        uses: ./.github/actions/setup-python-cached
        with:
          python-version: 3.12.13
          cache-tier: common
      - name: Install build dependencies
        run: |
          python -m pip install --upgrade pip
          pip install build twine
      - name: Build package
        run: python -m build
      - name: Check distribution
        run: twine check dist/*
      - name: Upload artifacts
        uses: actions/upload-artifact@v5
        with:
          path: dist/
          name: python-package-distributions

  publish-pypi:
    name: Publish to PyPI
    if: github.event_name == 'release' || (github.event_name == 'workflow_dispatch' && github.event.inputs.environment == 'pypi')
    needs: [build]
    runs-on: ubuntu-latest
    permissions:
      contents: read
    environment:
      name: pypi
      url: https://pypi.org/p/codex-ml
    steps:
      - name: Download artifacts
        uses: actions/download-artifact@v5
        with:
          path: dist/
          name: python-package-distributions
      - name: Publish to PyPI
        uses: pypa/gh-action-pypi-publish@ba38be9e461d3875417946c167d0b5f3d385a247
        with:
          password: ${{ secrets.PYPI_TOKEN }}
          skip-existing: false
    timeout-minutes: 45
```
