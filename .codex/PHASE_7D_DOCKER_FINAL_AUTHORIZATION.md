## CONTINGENCY PROCEDURES

### Scenario 1: Deployment Failure in Dev Stage

**If**: Dev environment deployment fails
**Then**:
1. Diagnose issue immediately
2. Attempt fix within 15 minutes
3. If not fixed: Escalate to @mbaetiong
4. **Do NOT proceed to staging**
5. Create incident ticket for post-mortem

### Scenario 2: Staging Validation Fails

**If**: Staging health checks fail or canary shows issues
**Then**:
1. Rollback to previous version in staging
2. Investigate root cause (max 30 minutes)
3. If issue identified and fix available: Re-deploy to staging
4. If issue NOT identified: Do NOT proceed to production
5. Escalate to @mbaetiong

### Scenario 3: Production Deployment Fails

**If**: Production health checks fail or error rate >1%
**Then**:
1. **IMMEDIATE ROLLBACK** to blue environment
2. Switch traffic back to v0.0.9-stable
3. Verify rollback successful (error rate normalizes)
4. **Halt deployment process**
5. Escalate to @mbaetiong with full incident details

### Scenario 4: Post-Deployment Critical Issue

**If**: Critical issue detected within 48 hours
**Then**:
1. Assess severity and customer impact
2. If critical (error rate >1%): Trigger rollback immediately
3. If high (error rate 0.1-1%): Implement hotfix or rollback
4. If medium: Monitor closely, plan fix release
5. If low: Document for next release
