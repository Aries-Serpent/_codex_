### fix(workflow): dedup path now re-triggers agent on existing session PR

**Problem:** When `copilot-session-chain.yml` detected an open session PR and
skipped creating a new one (deduplication), it posted no follow-up comment.
This left the agent with no trigger on the existing PR, causing subsequent
`@copilot continue` invocations to create unwanted sub-sub branches
(`copilot/sub-pr-*`) instead of committing to the already-open session branch.

**Fix:** Added a new step — `Re-trigger agent on existing session PR (dedup
path)` — that fires when `dedup_check.outputs.skip == 'true'`. It posts a
`@copilot continue` comment on the **existing** session PR with an explicit
`⚠️ IMPORTANT` note:
> Commit all changes **directly to this branch** and push to this PR.
> Do **NOT** create a new branch or open a new PR.

Updated the workflow summary step to reflect the dedup-trigger behavior.

**Files changed:**
- `.github/workflows/copilot-session-chain.yml` — added `retrigger_existing` step
