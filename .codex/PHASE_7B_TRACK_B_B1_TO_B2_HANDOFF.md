## 🔗 TEST PATTERN REFERENCE

### Use These Patterns for Test Generation

**Location:** `docs/TEST_DEVELOPMENT_PATTERNS.md` (if available)

**If not available, use these templates:**

#### Pattern 1: Error Handling Test
```python
def test_feature_error_condition():
    """Verify error handling for specific error condition."""
    # Arrange
    setup_initial_state()
    error_condition = prepare_error()

    # Act & Assert
    with pytest.raises(ExpectedError) as exc_info:
        function_under_test(error_condition)

    assert "specific_message" in str(exc_info.value)
    assert state_after_error_is_consistent()
```

#### Pattern 2: Boundary Condition Test
```python
def test_feature_boundary_condition():
    """Verify correct handling at boundary."""
    # Test with boundary values
    boundary_cases = [0, 1, -1, float('inf'), 'empty_string', None]

    for boundary_value in boundary_cases:
        result = function_under_test(boundary_value)
        assert_valid_output(result)
```

#### Pattern 3: Integration Test
```python
def test_integration_workflow():
    """Verify multi-step workflow execution."""
    # Setup
    component_a = ComponentA()
    component_b = ComponentB()

    # Execute workflow
    result_1 = component_a.process(input_data)
    result_2 = component_b.process(result_1)

    # Verify end-to-end
    assert result_2.is_valid()
    assert component_a.state == State.COMPLETE
    assert component_b.state == State.COMPLETE
```

## 🧠 TEST QUALITY REQUIREMENTS

### Each test MUST include:
1. **Clear docstring** — Describes what is being tested
2. **Arrange phase** — Setup, mocks, initial state
3. **Act phase** — Execute function under test
4. **Assert phase** — Verify expectations (≥2 assertions minimum)
5. **Specific validation:**
   - Return type and structure
   - Return values or error codes
   - State changes or side effects
   - Proper exception types and messages

### Test Naming Convention
