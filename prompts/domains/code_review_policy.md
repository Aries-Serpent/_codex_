# Code Review Policy

## Objectives
- Ensure correctness, safety, and compliance with repository standards.
- Ground all findings in retrieved code and policies; avoid speculation.

## Review Checklist
- Validate functional changes against requirements and tests.
- Check for security and privacy concerns; flag risky dependencies.
- Confirm logging, error handling, and feature flags follow repository patterns.
- Verify documentation and prompts are updated when behavior changes.

## Evidence Expectations
- Mark claims as `VERIFIED` only when citing file paths and line ranges or tool outputs.
- Use `UNKNOWN` when context is missing; request additional retrieval or diffs.
- Summaries must include risk level, blockers, and suggested tests.
