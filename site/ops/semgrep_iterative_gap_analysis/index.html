    Executive Summary¶

    This document tracks iterative gap analysis and remediation for the Semgrep SAST workflow. Each iteration identifies gaps, prioritizes by impact/risk, implements fixes, and updates the status until production-ready.

    Iteration 1: Initial Gap Analysis¶

    Gaps Discovered¶

    CRITICAL (P0) - Blocking Issues¶

    1. GAP-001: No Version Pinning for Semgrep CLI
    2. Risk: Breaking changes in semgrep updates could break CI
    3. Impact: High - Unpredictable CI failures
    4. Current: pip install --no-cache-dir semgrep (unpinned)
    5. Detection: Manual review

    6. Proposed Fix: Pin to known-good version (e.g., semgrep==1.52.0)

    7. GAP-002: No Version Pinning for PyTorch

    8. Risk: Torch API changes could break compatibility
    9. Impact: High - Unpredictable runtime errors
    10. Current: pip install --no-cache-dir torch --index-url ... (unpinned)

    11. Proposed Fix: Pin to stable version (e.g., torch==2.1.0)

    12. GAP-003: Missing SARIF Artifact Persistence

    13. Risk: SARIF results lost if upload fails
    14. Impact: High - No audit trail on upload failures
    15. Current: SARIF only uploaded, not saved as artifact
    16. Proposed Fix: Add actions/upload-artifact@v4 step

    HIGH (P1) - Production Blockers¶

    1. GAP-004: No Error Handling for Failed Scans
    2. Risk: Failing scan blocks PR merge even on non-critical findings
    3. Impact: Medium-High - Developer friction
    4. Current: No continue-on-error configuration

    5. Proposed Fix: Add conditional error handling based on severity

    6. GAP-005: Missing .gitignore for SARIF Artifacts

    7. Risk: Local SARIF files accidentally committed
    8. Impact: Medium - Repository pollution
    9. Current: No semgrep/SARIF patterns in .gitignore

    10. Proposed Fix: Add *.sarif.json, .semgrep_logs/ patterns

    11. GAP-006: No Job Timeout Configuration

    12. Risk: Hung jobs consume runner resources
    13. Impact: Medium - Resource waste
    14. Current: Default 6-hour timeout

    15. Proposed Fix: Set reasonable timeout (e.g., 30 minutes)

    16. GAP-007: No Manual Workflow Trigger

    17. Risk: Cannot manually re-run scans without code change
    18. Impact: Medium - Operational friction
    19. Current: Only push and pull_request triggers
    20. Proposed Fix: Add workflow_dispatch trigger

    MEDIUM (P2) - Quality & Maintainability¶

    1. GAP-008: Limited Caching Scope
    2. Risk: Cache misses due to narrow key
    3. Impact: Low-Medium - Longer CI times
    4. Current: Only caches based on requirements.txt/pyproject.toml

    5. Proposed Fix: Add fallback cache key without hash

    6. GAP-009: No Semgrep Config Validation

    7. Risk: Invalid config causes runtime failures
    8. Impact: Low-Medium - Delayed feedback
    9. Current: No pre-run validation

    10. Proposed Fix: Add validation step using semgrep --validate

    11. GAP-010: Missing Job Summary/Reporting

      • Risk: Poor visibility into scan results
      • Impact: Low-Medium - Poor observability
      • Current: Results only in SARIF/logs
      • Proposed Fix: Add GitHub step summary with key metrics

    12. GAP-011: No Concurrency Controls

      • Risk: Multiple concurrent runs waste resources
      • Impact: Low-Medium - Resource waste
      • Current: No concurrency limits
      • Proposed Fix: Add concurrency group with auto-cancel

    LOW (P3) - Nice-to-Have¶

    1. GAP-012: No Scheduled Scans

      • Risk: Miss new vulnerabilities in unchanged code
      • Impact: Low - Delayed detection
      • Current: Only event-triggered
      • Proposed Fix: Add per-phase scheduled scan

    2. GAP-013: Inconsistent with Other Security Workflows

      • Risk: Confusion, duplication
      • Impact: Low - Maintainability
      • Current: Different structure than security-suite.yml, codeql-analysis.yml
      • Proposed Fix: Align trigger conditions and permissions

    3. GAP-014: No Integration with security-suite.yml

      • Risk: Duplicate scanning effort
      • Impact: Low - Resource waste
      • Current: Standalone workflow
      • Proposed Fix: Consider merging into unified suite

    Prioritized Remediation Plan¶

    Phase 1: Critical Fixes (P0) - IMPLEMENT NOW¶

    1. GAP-001 & GAP-002: Pin semgrep and torch versions
    2. GAP-003: Add SARIF artifact upload

    Estimated Impact: Eliminates unpredictability, adds audit trail
    Effort: 15 minutes

    Phase 2: Production Blockers (P1) - IMPLEMENT NEXT¶
